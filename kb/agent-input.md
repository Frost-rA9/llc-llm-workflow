# agent-input · 角色指南写作输入契约（Phase C2）

> **本文件是并行 agent 的唯一输入契约。** 任何角色指南的写作都必须按本文件执行；
> 与 `kb/口径.md` 冲突时以 `kb/口径.md` 为准。
> **版本**：v1（2026-09-20）· 适用：`kb/style/角色/*.md`（13 份）

---

## 0. 一句话任务

读取 `build/packs/<角色>.md`（证据包），写出一份 `kb/style/角色/<角色>.md`，
**引用 ≥5 处、指标 ≥3 类、数字全部可复算**，然后跑 `tools/lint_kb.py` 到 0 FAIL。

## 3. 硬约束（lint 会拦）

| 断言 | 门槛 | 说明 |
|---|---|---|
| `A1` 引用可解析 | `@@` 残留 **0**；所有 `文件#id` 命中语料 | 引用的 id 必须真实存在 |
| `A2` 数字可复算 | 与 `voice.py` 输出**误差 0** | 写法见 §4 |
| `A3` 术语有来源 | 无来源条目 **0** | 称呼表/自称表/易错点每条带来源 |
| `S1` 引用 ≥5 处 | ≥ 5 | 数的是出现次数 |
| `S2` 指标 ≥3 类 | ≥ 3 类（M1–M8） | 如 M2 + M4 + M7 |
| `F1` 头部规范 | 5 字段齐全 | 见 §2 第 1 节 |

**自检命令（交付前必须跑，退出码须为 0）**：

```bash
python3 tools/voice.py --resolve kb/style/角色/<角色>.md   # 回填占位符
python3 tools/lint_kb.py kb/style/角色/<角色>.md           # 必须 FAIL 0
```

### 3.1 断言抓不到的 3 条写作纪律（lint 不拦，C4 审阅项）

> 这三条在 `lint_kb.py` 的射程之外（属“说法是否站得住”），但直接决定文档可信度。
> 以实玛利样张与李箱 pilot 各踩中过，故硬化为纪律。

| # | 纪律 | ❌ 反例 | ✅ 正确 |
|---|---|---|---|
| **D1** | **身份/背景断言必须配内联 `文件#id`**，且该引用要**真的支持这句断言**（不能随便挂一个不相关的例句） | 「九人会出身的都市研究者」（引的是讲镜子技术的 `4D107B#28`） | 「九人会出身的都市研究者」（`[StoryData/4D207B.json#0]`「九人会的崩裂粉碎了一切」） |
| **D2** | **对比性断言**（最高/最低/偏低/全队第 N）必须给出 **`voice.py --table` / `--compare` 来源**，或**改为定性表述**（不加未复算的数字） | 「均中字 18.7 低于全队均值」（均值未给出来源） | 「均中字 18.7（M2），在 13 角色中偏低（`python3 tools/voice.py --table` 可复核）」 |
| **D3** | **EN→CN 映射列**（如 `isn't it? → 吗`）若 pack 无直接证据，须**标注「推断」**，或改用 pack §4 实例能直接支撑的说法 | `\| isn't it? \| 吗 \| 8.2 \|`（pack 无此 EN 证据） | `\| isn't it?（推断） \| 吗 \| 8.2 \|` 或换成 pack §4 有实例的口癖 |

**判定方式**：C4 横向一致性审阅会逐份抽查这三项；抽查不通过则退回重写该节。

## 4. 数字写法（A2 的可见性规则）

**每个数字必须能被工具重算。** 三种合法写法：

```markdown
✅ 单指标值（带公式编号，值前可加 **）
   均中字 **20.5**（M2）     行尾"。" 46.5%（M7）     句数 2265（M1）
   `……` M4 = 75.5（M4）

✅ 表格：表头写指标、行首写模式（工具逐格复算）
   | 项 | M4 每百句 | M6 行级% | M7 行尾% |
   | `……` | 75.5 | 60.4 | 26.4 |

✅ 派生值：必须写成算式（工具会验算）
   3.1 + 2.9 + 0.7 = 6.7（M4 敬语合计）

✅ 辅助证据（E1–E3）：写数值即可，工具已白名单；跨角色值必须来自 --compare
   主题语域 **6.1% 行**（E1）　敬称三层 KR 9.4% / EN 0.1% / CN 6.4%（E2）
   | 排名 | 角色 | 敬称行占比（E2-cn） | 行数 |   ← 表头带 E2-cn，工具逐行用该角色的值复算
```

**会被判 FAIL 的写法**：

```markdown
❌ 均中字 21.4（M2）        ← 21.4 是对账口径 M2_text，不是 M2（应为 20.5）
❌ 你 17.4                   ← 裸小数且不在指标集内（你 M4=19.9 / M6=17.1）
❌ `……` 150.8               ← 旧「按字符计」值；现行口径 = 75.5
❌ 敬语合计 6.7              ← 合计未列加数，无法验算（改用 `=` 算式）
```

**允许的近似**：`≈` / `约` / `~` / `±` 前缀，或行内含 `派生` / `合计`
→ 不判 FAIL，但会记 WARN，请尽量改用算式。

> ⚠️ **只准用 `build/packs/<角色>.md` 里的数字**。pack 里没有的指标，不要写、不要估。
> 对账列 `M2_text` / `M3_text` **不进交付 md**，只留在证据包（口径 §2.3）。

## 5. 引用与例句写法

**写作阶段只允许写占位符，禁止手抄例句**（口径 §四）：

```markdown
@@<kr_model>|<逻辑文件>|<id>@@
例：@@이스마엘|StoryData/S709B.json|37@@
```

- `<kr_model>`：角色基准 model（pack §0 给出，如 `이스마엘`）
- `<逻辑文件>`：不带语言前缀、含 `.json`（如 `StoryData/S709B.json`）
- `<id>`：`dataList` 里的 `id`/`key`
- 候选行直接抄 pack §4 的 `@@…@@` 原文

**回填后**：占位符会被替换为 `EN: … ｜ CN: …`。引用标记仍要单独写：

```markdown
1. `[StoryData/S709B.json#37]`（M4 29.0）
   - EN: `@@이스마엘|StoryData/S709B.json|37@@`
```

**禁止**：写不存在的 id；写 `…` 之类的伪 id；写 `[StoryData/xxx.json#…]`。

## 6. 权威分层（口径 §六）

| 等级 | 用途 | 处置 |
|---|---|---|
| `零协权威` | 零协 Release 已有的中文 | **不可改**，不得覆盖 |
| `自拟待确认` | 本工作流产出的新说法 | 单独成栏 + 生成方式 + 日期 + 退役条件 |

**禁止**把自拟条目混进权威栏。零协已发布的中文译名一律照抄（用 `corpus.py grep` 确认）。

## 7. 引用来源（只允许本仓语料）

- **引用的唯一合法来源是 `corpus/`**（零协 Release + 游戏本体三语），经 `tools/` 检索。
- 任何**外部汉化 / 知识库 / 现成指南**一律**不得作为引用来源**，也不得写进交付 md：
  它们只可用于**内部对账**（校准口径、校验数字），且**不进 `kb/`**。
- 交付 md 里出现的每一处 `[文件#id]` 必须能在 `corpus/` 中命中（A1 断言强制）。
- 权威分层只认 `零协权威` / `自拟待确认` 两档（口径 §六）。

## 8. 交付物与完成定义（DoD）

1. `kb/style/角色/<角色>.md` 写入完毕，10 节齐全；
2. `python3 tools/voice.py --resolve <该文件>` 回填成功，`@@` 残留 0；
3. `python3 tools/lint_kb.py <该文件>` **FAIL 0**（WARN 需逐条说明或消除）；
4. 在提交信息/回执中给出：`引用 N 处 / 指标 M 类 / lint 结果`。

## 9. 禁止事项（红线）

| # | 禁止 | 原因 |
|---|---|---|
| 1 | 改 `corpus/`、`build/`、别人的 `kb/style/角色/*.md` | 只读输入 / 并行写冲突 |
| 2 | 手抄 EN/CN 例句 | 会与语料不一致，A1/A2 无法收口 |
| 3 | 编造 pack 中不存在的数字 | A2 直接 FAIL |

| 5 | 用 `encoding="utf-8"` 直读语料 | 9 个文件带 BOM，会静默丢 1,035 行 |
| 6 | 把 `……` 按字符计（×2） | 口径 G5：按连续串计 **1 次** |
| 7 | 跨角色数字凭记忆写 | 必须来自 `python3 tools/voice.py --compare` |
